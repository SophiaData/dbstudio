# MySQL 管理与诊断

本页说明 MySQL 专属的对象管理能力：分区、索引、会话、事件、用户权限、对象搜索、字段血缘、对象源码与新建库。

**入口**：在左侧数据库导航里，对任意节点（连接、表、视图）点 `⋯` 打开右键菜单，选择「MySQL 管理…」。

面板共 9 个页签。表相关的页签（分区、索引、字段血缘）需要先在树里选中一张表。

---

## 分区

分区表的每个分区会作为**独立节点**显示在表下面，节点名带边界值（例如 `p2024  (< 2025)`）。

在「分区」页签可以新增 RANGE 分区：

- **分区名**：例如 `p2026`
- **边界值**：数字，或 `MAXVALUE`

### 为什么分区值得单独做

DBeaver 的表分区管理（#2627）和"修改已有索引"（#9329）都是长期未关闭的需求；dbx 的分区同样未支持。这两项在这里可用。

### 事务边界

分区变更是 DDL，会隐式提交。**当前连接有未提交事务时会直接拒绝**，不会悄悄把你的事务一起提交掉。

### 子分区表

`SUBPARTITION BY ...` 的表在 MySQL 内部是按每个子分区一行返回的。这里按分区名聚合成一条，并记录 `subpartitionCount`，不会出现重复节点。

---

## 索引

在「索引」页签可以新增普通索引、唯一索引和删除索引。

索引名与列名有白名单校验：只接受字母、数字、下划线、`$`，最长 64 字符。不接受反引号或嵌入片段。

修改既有索引走**单条 `ALTER TABLE ... DROP INDEX x, ADD INDEX y`**——中间不会出现"旧索引已删、新索引没建"的空窗。

---

## 会话

「会话」页签列出 `information_schema.PROCESSLIST` 的全部连接：ID、用户、来源、库、命令、状态、执行秒数。

- **当前会话**会被标记为「当前」，它的终止按钮是禁用的——避免把自己杀掉
- 终止其他会话前会弹确认框

---

## 事件

「事件」页签读取 `information_schema.EVENTS`，并显示事件调度器（`event_scheduler`）当前状态。

调度器关闭时事件不会执行，这一栏能直接看出来。

`CREATE EVENT` / `DROP EVENT` 走文本协议执行（MySQL 的预处理语句协议不支持这类语句，会报 1295）。

---

## 用户权限

「用户权限」页签读取 `mysql.user` 与 `information_schema.USER_PRIVILEGES`。

**不会返回口令或密码哈希。**

可以执行的操作：

- **新建账号**：账号名 + 主机（默认 `%`）+ 口令（可留空）
- **删除账号**
- **授予 / 回收权限**：权限清单 + 授权范围

### 四层白名单

账号名、主机、权限清单、授权范围全部走白名单校验：

- 权限只接受固定枚举（`SELECT`、`INSERT`、`ALL PRIVILEGES` 等），不接受任意字符串
- 授权范围只支持 `global` / `database` / `table` 三种形态
- 口令按 MySQL 字符串字面量转义（先转义反斜杠再转义单引号），避免反斜杠被解释成转义符

---

## 对象搜索

「对象搜索」页签可以跨库按名称搜索表、视图、列、例程与触发器。

- 关键字支持中文与符号
- 输入里的 `%` 和 `_` 按**字面量**处理，不会变成 LIKE 通配符
- 每条结果都带可直接定位的节点 ID

结果有条数上限；达到上限时会提示"结果已截断"。

---

## 字段血缘

「字段血缘」页签回答两个问题：这个字段从哪来、谁在用它。

在树里选中表、输入列名后读取。证据按**可信度分档**，不会把猜测当成事实：

| 来源 | 可信度 | 含义 |
|---|---|---|
| 外键 | **确定** | 数据库声明了约束 |
| 视图定义 | **可能** | 视图同时引用了目标表与目标列 |
| 同名列 | **可能** | 仅按名称推测，需要业务确认 |

这一分档口径与 dbx 的字段血缘一致。

**只出现同名列**时仍会列出，但明确标为"可能"，并提示需要人工确认。

---

## 对象源码

「对象源码」页签读取视图、存储过程、函数、触发器的真实源码。

源文本走全量读取，不会被截断成预览片段。

---

## 新建库

「新建库」页签接受库名创建数据库，库名同样走白名单校验（字母、数字、下划线、`$`）。

已存在同名库时不会覆盖。

---

## 执行 SQL 文件

工具栏的「打开 SQL 文件」可以选一个 `.sql` 文件并送入编辑器执行。

- 只接受 `.sql` 后缀，上限 16 MiB
- 必须由你在系统文件对话框里亲手选择——应用不会读任意路径
- 拆分、参数绑定、逐条执行、错误处理与手输脚本完全一致

---

## 相关的验证方式

真库验收需要一台可达的 MySQL 8，设置以下环境变量后运行：

```
PARTITION_TEST_HOST=127.0.0.1
PARTITION_TEST_PORT=13306
PARTITION_TEST_DATABASE=testdb
PARTITION_TEST_USER=<测试账号>
PARTITION_TEST_PASSWORD=<测试口令>
```

```
cargo test -p dbstudio-drivers
cargo test -p dbstudio-core --test native_mysql_management_live
node apps/desktop/tests/audit-ui-regressions.mjs
```

未设置 `PARTITION_TEST_HOST` 时真库用例会显式跳过，不会静默通过。

各项能力与 dbx / DBeaver 的覆盖对照、以及界面实测记录见 [MySQL 能力矩阵](../support/mysql-capability-matrix.md)。
