# SQL 工作台

本页说明怎么写和执行 SQL：多语句脚本、参数、执行计划、取消，以及结果怎么显示。

---

## 执行 SQL

在工作台里写 SQL，点执行。

- **多语句**：一次可以写多条语句，按方言的规则切分后**顺序执行**。中途某条出错会中断后面的语句，并指出是哪一条失败了。
- **执行中的查询**可以取消（能不能真取消取决于数据库，见下文「取消」）。

### 带参数的 SQL

用占位符写参数，执行时在参数面板里填值：

| 数据库 | 占位符写法 |
|---|---|
| SQLite | `?`（位置参数） |
| PostgreSQL | `$1`、`$2` … |
| MySQL / MariaDB | `?`（位置参数） |

例如 PostgreSQL：

```sql
SELECT * FROM users WHERE id = $1 AND email = $2
```

参数值**通过绑定传入**，不是拼进 SQL 字符串。这样既不会被引号或特殊字符搞坏 SQL，也避免了注入。

## 执行计划（EXPLAIN）

点「执行计划」可以看到数据库打算怎么执行这条查询。

- **SQLite**：用 `EXPLAIN QUERY PLAN`，显示扫描/索引使用情况。
- **PostgreSQL**：用 `EXPLAIN (FORMAT JSON)`，以树形结构展示。
- **MySQL / MariaDB**：使用方言的 `EXPLAIN` 结果，显示访问类型、候选索引和扫描信息。

注意两点：

- 执行计划反映的是**当前这条语句**。如果之后断开连接或改了语句，旧的计划会被清掉，不会停留在界面上让你误以为是新语句的计划。
- 执行计划**不执行**查询本身，不会改数据。

## 取消执行中的查询

能不能真的停下来，取决于数据库：

| 数据库 | 能否取消 | 说明 |
|---|---|---|
| PostgreSQL | ✅ 真取消 | 在服务端终止该查询 |
| MySQL / MariaDB | ✅ 真取消 | 使用 `KILL QUERY` 终止该查询 |
| SQLite | ❌ 不能 | 驱动是同步 API，没有中断接口 |

对 SQLite，界面会**如实告诉你"当前驱动不支持取消"**，而不是让你以为点了就停了。这不是偷懒，是这个数据库驱动本身没法在中途打断。

## 结果怎么显示

结果会根据语句类型显示成不同形态：

- **查询（SELECT）**：显示表格，支持分页、排序、筛选。
- **DML（INSERT / UPDATE / DELETE）**：显示「受影响行数」卡片。
- **DDL（CREATE / ALTER / DROP）**：显示变更摘要卡片。

结果集采用**分页**加载，不是一次把全部行拉进内存。所以百万行的表也能打开——只是往下翻时会按需再取。

> 已知代价：SQLite 的深翻页是 `LIMIT ? OFFSET ?`，越往后翻数据库要跳过的行越多，会慢一些。这是已知问题，根治需要键集分页，属后续阶段。

## 历史与收藏

- **SQL 历史**：执行过的语句会被记录，可以回看和重新执行。
- **收藏**：常用的 SQL 可以收藏，方便反复使用。

（对应验证：`test:sql-library`、`test:gui-sql-library`。）

## 草稿按连接保存

你在某个连接的编辑器里写的、还没执行的 SQL，会作为**草稿**跟着这条连接走。切到别的连接再切回来，草稿还在，不会串到别的连接。

（对应验证：`test:gui-sql-draft`。）

---

## 和事务的关系

- 每一组编辑 / 执行都归属到**发起它的那条连接**。
- 不同的连接、不同的标签，事务状态是**彼此独立**的，一个标签的提交不会影响另一个标签的未提交修改。

（对应验证：`test:gui-mutation-transaction`、`test:gui-sql-transaction`。）
