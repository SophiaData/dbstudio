# SQL 工作台

本页说明怎么写和执行 SQL：多语句脚本、参数、执行计划、取消，以及结果怎么显示。

---

## 执行 SQL

在工作台里写 SQL，点执行。

- **多语句**：一次可以写多条语句，按方言的规则切分后**顺序执行**。中途某条出错会中断后面的语句，并指出是哪一条失败了。
- **执行中的查询**可以取消（能不能真取消取决于数据库，见下文「取消」）。

### 按表别名补全字段

在普通 `SELECT` 或 `JOIN` 查询中，输入 `u.` 会提示该别名指向的表字段，例如 `SELECT u. FROM sales.users AS u`。请先在当前连接的元数据树展开表，或打开表的结果页。遇到同名表时，在 `FROM` 或 `JOIN` 里写明库或 schema。

别名补全覆盖单层查询。子查询、CTE 和集合查询的别名作用域暂未支持。

### 带参数的 SQL

用占位符写参数，执行时在参数面板里填值：

| 数据库 | 占位符写法 |
|---|---|
| SQLite | `?`（位置参数） |
| PostgreSQL | `$1`、`$2` … |
| MySQL / MariaDB | `?`（位置参数） |

例如 PostgreSQL：

```sql
SELECT * FROM users WHERE id = $1 AND email = $2
```

参数值**通过绑定传入**，不是拼进 SQL 字符串。这样既不会被引号或特殊字符搞坏 SQL，也避免了注入。

## 执行计划（EXPLAIN）

点「执行计划」可以看到数据库打算怎么执行这条查询。

- **SQLite**：用 `EXPLAIN QUERY PLAN`，显示扫描/索引使用情况。
- **PostgreSQL**：用 `EXPLAIN (FORMAT JSON)`，以树形结构展示。
- **MySQL / MariaDB**：使用方言的 `EXPLAIN` 结果，显示访问类型、候选索引和扫描信息。

注意两点：

- 执行计划反映的是**当前这条语句**。如果之后断开连接或改了语句，旧的计划会被清掉，不会停留在界面上让你误以为是新语句的计划。
- 执行计划**不执行**查询本身，不会改数据。

## 取消执行中的查询

能不能真的停下来，取决于数据库：

| 数据库 | 能否取消 | 说明 |
|---|---|---|
| PostgreSQL | ✅ 真取消 | 在服务端终止该查询 |
| MySQL / MariaDB | ✅ 真取消 | 使用 `KILL QUERY` 终止该查询 |
| SQLite | ❌ 不能 | 驱动是同步 API，没有中断接口 |

同一连接会等取消调用返回后再开始下一条 SQL。原查询是否取消成功，以它的实际执行结果为准。

对 SQLite，界面会**如实告诉你"当前驱动不支持取消"**，而不是让你以为点了就停了。这不是偷懒，是这个数据库驱动本身没法在中途打断。

## 结果怎么显示

结果会根据语句类型显示成不同形态：

- **查询（SELECT）**：显示表格，支持分页、排序、筛选。
- **DML（INSERT / UPDATE / DELETE）**：显示「受影响行数」卡片。
- **DDL（CREATE / ALTER / DROP）**：显示变更摘要卡片。

结果集采用**分页**加载，不是一次把全部行拉进内存。所以百万行的表也能打开——只是往下翻时会按需再取。

> 已知代价：SQLite 的深翻页是 `LIMIT ? OFFSET ?`，越往后翻数据库要跳过的行越多，会慢一些。这是已知问题，根治需要键集分页，属后续阶段。

### 多列排序

点击列头按该列排序，再点击切换升降序。按住 Shift 点击其他列，会把它追加到排序顺序中。列头的数字表示排序优先级，例如 `↑1` 表示第一列升序。按住 Shift 重复点击已排序的列，可依次切换为降序和移除该列。

点击「清除排序」会移除网格加上的排序，保留筛选条件和原 SQL。调整排序后从第一页重新加载结果。

### 复制选中行

勾选当前页的行后，点「复制选中行」。剪贴板包含表头和数据列，按网格的行序和列序提供制表符分隔文本。已暂存的单元格修改按点击时的显示值复制。含制表符、换行或双引号的字段会用双引号包住，字段内的双引号会写成两个。`NULL` 复制为空字段。复制前会获取被截断字段的全文，读取失败时保留原剪贴板。

## 历史与收藏

- **SQL 历史**：执行过的语句会被记录，可以回看和重新执行。
- **收藏**：常用的 SQL 可以收藏，方便反复使用。

（对应验证：`test:sql-library`、`test:gui-sql-library`。）

## SQL 标签和草稿

点「新建 SQL 标签」即可在当前连接下另开一份草稿。每个标签保存自己的 SQL 和连接，重启后恢复仍打开的标签。打开 SQL 文件、载入历史或收藏时，新建标签保留当前草稿。关闭有内容的标签前会确认。

用「SQL 连接」切换到相应连接的标签。对象树和结果标签各自保留其上下文。执行按钮和参数弹窗使用发起时的 SQL 标签和连接。若连接已关闭、更新或移除，先确认目标并重新发起查询。

MySQL 标签显示连接配置里的默认库。使用不同库时可分别建立连接。手动执行 `USE` 会改变该连接的会话默认库，并影响同连接的其他标签。

首次打开会恢复旧版按连接保存的草稿。格式未知或无法写入时，工作台提示当前会话的草稿保留在内存中。

## 和事务的关系

- 每一组编辑 / 执行都归属到**发起它的那条连接**。
- 事务是**连接级**的：同一连接的所有标签共享事务状态，不同连接之间互相独立。
- 点「提交」会先应用同连接所有标签的未应用修改，再提交该连接事务；点「回滚」会放弃同连接所有标签的本地修改及未提交事务。

（对应验证：`test:gui-mutation-transaction`、`test:gui-sql-transaction`。）
