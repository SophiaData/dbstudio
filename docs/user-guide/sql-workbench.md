# SQL 工作台

本页说明怎么写和执行 SQL：多语句脚本、参数、执行计划、取消，以及结果怎么显示。

---

## 编辑 SQL

编辑区显示行号、语法高亮、当前行和匹配括号。Tab/Shift+Tab 可调整所选行的缩进，Ctrl/Cmd+Z 撤销，Windows 上 Ctrl+Y 或 Ctrl+Shift+Z 重做，macOS 上 Cmd+Shift+Z 重做。格式化和接受字段补全也可撤销。

切换仍打开的 SQL 标签时，各自保留当前会话内的撤销记录、光标、选区和滚动位置。重启后恢复 SQL 草稿，撤销记录不跨应用重启保存。中文输入法组合输入期间，Enter 用于确认输入，不执行 SQL。

Ctrl/Cmd+Enter 执行选区或当前语句，Shift+Enter 执行全部；补全列表打开时这些执行键仍然有效。普通 Enter/Tab 接受补全，Esc 关闭列表。

### 查找、替换与折叠

点击「查找」或按 Ctrl/Cmd+F 打开当前 SQL 标签的搜索面板。支持区分大小写、全词匹配和正则表达式；Enter/Shift+Enter 查找下一处/上一处，F3/Shift+F3 也可定位匹配，Esc 关闭面板。搜索框中的 Enter 不执行 SQL。

点击「替换」或按 Windows Ctrl+H、macOS Cmd+Option+F 聚焦替换输入框。可以逐处替换或全部替换；全部替换后一次 Ctrl/Cmd+Z 即可撤销。查找范围为当前 SQL 草稿，包括注释与字符串；替换不会自动执行 SQL。编辑器只读时可查找，不能替换或注释。

选中多行后，点击「行注释」或按 Ctrl/Cmd+/，添加或取消 `--` 行注释。点击行号旁箭头可折叠或展开多行语句、块注释；折叠只影响显示，执行仍使用完整 SQL 文本。Windows Ctrl+Shift+[/]（macOS Cmd+Option+[/]）折叠/展开当前区域，Ctrl+Alt+[/] 折叠/展开全部。

「自动换行」开关只调整显示，不向 SQL 插入换行。折叠、换行开关及搜索状态按仍打开的 SQL 标签在当前会话保留，重启后不恢复这些显示状态。

## 执行 SQL

在工作台里写 SQL，点执行。

- **多语句**：一次可以写多条语句，按方言的规则切分后**顺序执行**。中途某条出错会中断后面的语句，并指出是哪一条失败了。
- **执行中的查询**可以取消（能不能真取消取决于数据库，见下文「取消」）。

### 失败语句定位

执行失败时，结果区域保留原始错误、本次第几条语句及行号。点击「定位执行语句」会切回发起执行的 SQL 标签，展开被折叠的区域并选中整条语句。当前语句或选区执行也使用原草稿的行号；没有来源范围时明确显示「执行片段」行号。

定位依据执行时保存的草稿快照。草稿已修改或原标签已关闭时，定位按钮禁用，可展开「查看执行快照」查看当时发送的语句，不覆盖当前草稿。参数值不包含在快照中。当前后端没有统一的错误字符位置，定位到整条语句，不标记推测的错误列。

若数据库已返回执行成功，但后续结果处理或事务状态刷新失败，会明确提示「语句已执行，后续处理失败」。此时先核对结果，避免直接重试写语句。

### 按表别名补全字段

在普通 `SELECT` 或 `JOIN` 查询中，输入 `u.` 会提示该别名指向的表字段，例如 `SELECT u. FROM sales.users AS u`。请先在当前连接的元数据树展开表，或打开表的结果页。遇到同名表时，在 `FROM` 或 `JOIN` 里写明库或 schema。

别名补全覆盖单层查询。子查询、CTE 和集合查询的别名作用域暂未支持。

### 带参数的 SQL

用占位符写参数，执行时在参数面板里填值：

| 数据库 | 占位符写法 |
|---|---|
| SQLite | `?`（位置参数） |
| PostgreSQL | `$1`、`$2` … |
| MySQL / MariaDB | `?`（位置参数） |

例如 PostgreSQL：

```sql
SELECT * FROM users WHERE id = $1 AND email = $2
```

参数值**通过绑定传入**，不是拼进 SQL 字符串。这样既不会被引号或特殊字符搞坏 SQL，也避免了注入。

## 执行计划（EXPLAIN）

点「执行计划」可以看到数据库打算怎么执行这条查询。

- **SQLite**：用 `EXPLAIN QUERY PLAN`，显示扫描/索引使用情况。
- **PostgreSQL**：用 `EXPLAIN (FORMAT JSON)`，以树形结构展示。
- **MySQL / MariaDB**：使用方言的 `EXPLAIN` 结果，显示访问类型、候选索引和扫描信息。

注意两点：

- 执行计划反映的是**当前这条语句**。如果之后断开连接或改了语句，旧的计划会被清掉，不会停留在界面上让你误以为是新语句的计划。
- 执行计划**不执行**查询本身，不会改数据。

## 取消执行中的查询

能不能真的停下来，取决于数据库：

| 数据库 | 能否取消 | 说明 |
|---|---|---|
| PostgreSQL | ✅ 真取消 | 在服务端终止该查询 |
| MySQL / MariaDB | ✅ 真取消 | 使用 `KILL QUERY` 终止该查询 |
| SQLite | ❌ 不能 | 驱动是同步 API，没有中断接口 |

同一连接会等取消调用返回后再开始下一条 SQL。原查询是否取消成功，以它的实际执行结果为准。

对 SQLite，界面会**如实告诉你"当前驱动不支持取消"**，而不是让你以为点了就停了。这不是偷懒，是这个数据库驱动本身没法在中途打断。

## 结果怎么显示

结果会根据语句类型显示成不同形态：

- **查询（SELECT）**：显示表格，支持分页、排序、筛选。
- **DML（INSERT / UPDATE / DELETE）**：显示「受影响行数」卡片。
- **DDL（CREATE / ALTER / DROP）**：显示变更摘要卡片。

结果集采用**分页**加载，不是一次把全部行拉进内存。所以百万行的表也能打开——只是往下翻时会按需再取。

> 已知代价：SQLite 的深翻页是 `LIMIT ? OFFSET ?`，越往后翻数据库要跳过的行越多，会慢一些。这是已知问题，根治需要键集分页，属后续阶段。

### 每页行数

在结果底部选择每页 100、200、500 或 1,000 行，默认 200。每个结果标签独立保存当前会话内的设置；更改后通过当前游标回到第一页，后续翻页、刷新和筛选继续使用该设置。取页失败时保留原页与原页大小，成功后才更新显示。

有未应用的本地修改时，会先询问应用、放弃或取消。取消更改会保留原页、行数设置、选区和全部草稿；若先应用修改、随后取页失败，则保留应用后的刷新结果，修改仍处于未提交事务中，不自动回滚。正在编辑单元格或新增行时，需先保存或取消表单，再更改分页。

### 服务端筛选与本页搜索

「服务端筛选」按条件重新查询数据库，并回到第一页；「已应用服务端筛选」显示当前结果实际使用的条件。输入框中的条件在点击「应用筛选」且查询成功前不代表已生效。无效条件会先提示错误，不会先应用或丢弃草稿；取消草稿确认或查询失败后，当前结果及已应用条件保持原状。

「本页搜索」只查找当前页已加载的可见单元格，忽略大小写，包含已暂存的显示值；隐藏列不参与，长字段只查找已加载预览。它会给匹配值加下划线，不筛掉行、不查询数据库，也不代表全表搜索。「上一个匹配」「下一个匹配」或输入框内 Enter/Shift+Enter 可循环定位并聚焦单元格。翻页后保留搜索词并重新计算匹配，切换结果标签后清空搜索；没有匹配时定位按钮禁用。

总行数通过 COUNT 按需统计，针对完整对象、不含服务端筛选，也不应用本地草稿。PostgreSQL/MySQL 统计期间可点「取消统计」；发出请求后仍等待后端结束，确认中止才显示「统计已取消」。如果统计先完成，保留真实结果。取消失败或未找到正在执行的统计时会提示并允许重试，不提前解锁连接。SQLite 当前不支持取消统计，会明确提示等待结果。

切换标签后，统计继续归属于原标签，返回原标签仍可取消；结果页或对象已变化时，旧统计结果不会更新新页面。超出 JavaScript 安全整数范围的统计值会提示错误，不显示失真的总数。

### 多列排序

点击列头按该列排序，再点击切换升降序。按住 Shift 点击其他列，会把它追加到排序顺序中。列头的数字表示排序优先级，例如 `↑1` 表示第一列升序。按住 Shift 重复点击已排序的列，可依次切换为降序和移除该列。

点击「清除排序」会移除网格加上的排序，保留筛选条件和原 SQL。调整排序后从第一页重新加载结果。

### 调整列宽与跳转列

拖动列头右边缘可调整列宽，双击边缘可按列名和当前页内容适宽。「适宽全部列」批量调整当前结果的列宽，「重置列宽」恢复每列 160 像素。列宽限制在 72–720 像素，超长内容仍可通过「查看完整值」读取；适宽只测量已加载的预览，不额外获取大字段全文。

列头右边缘也可用 Tab 聚焦：左右方向键每次调整 10 像素，Shift 加方向键每次 40 像素，Home/End 调到最小/最大宽度，Enter 适宽。拖动过程中按 Esc 或窗口失去焦点会取消本次调整。

在「跳转列」输入列名片段，从「匹配列」选中目标后点击「跳转」或按 Enter。匹配不区分大小写，同名列用序号区分；目标列会滚动到可见区域并高亮列头。跳转不改变排序、数据或原来的单元格选择。

仍打开的每个结果标签分别保留列宽、固定/隐藏状态和横向滚动位置；分页或刷新后列结构相同时继续沿用。列名、类型或顺序改变时重置布局；关闭标签或重启应用后不保留。

### 固定、隐藏与恢复列

在「匹配列」选择目标后，点击「固定此列」或「隐藏此列」。固定列排列在左侧，同组内保持原始列顺序，横向滚动时仍可见。行号始终保留在左侧。固定列太宽时，部分固定列会临时随表格滚动，并显示提示；缩小列宽或加宽窗口即可恢复固定，始终给其他列留出操作区域。

隐藏后可在匹配列表中找到标有「隐藏」的列，点「显示此列」恢复；跳转隐藏列也会先恢复它。「显示全部列」恢复全部隐藏列，「取消全部固定」恢复原始列序。至少保留一列可见；可见列或列顺序改变时清除单元格选区，已暂存的数据修改继续保留。

复制整行、复制选中行及批量粘贴均采用**当前可见列顺序**，隐藏列不参与。隐藏主键不会丢失修改行的定位依据。「导出当前页」仍按原始顺序导出全部结果列，包括隐藏列；隐藏只影响网格显示，不限制数据访问。

### 键盘选择与矩形复制

点击单元格后用上下左右方向键移动，范围限定在当前页；隐藏列会跳过，固定列按当前显示位置参与移动。按住 Shift 加方向键，或按住 Shift 点击另一单元格，可从最初的单元格扩展、缩小或反向选择矩形。Esc 将选区收回到当前单元格；Tab 继续切换焦点，Enter 保留编辑或查看完整值的功能。

选好矩形后按 Ctrl/Cmd+C 或点「复制选区」，复制不含表头的 TSV 文本；点「复制选区（含表头）」会在第一行加入列名。只复制选区内的可见列，使用复制时已暂存的显示值。NULL 输出为未加引号的 `\N`，空字符串为 `""`，文字 `\N` 为 `"\N"`；含制表符、换行或双引号的字段也会引用并转义，整数和小数保留原有精度。不含表头的数据可粘贴回满足编辑条件的 MySQL 区域。

复制被截断的大字段前先读取全文；读取失败或仍被截断时提示错误，保留原剪贴板。读取期间改变选区、切换标签、分页或刷新会放弃此次复制。可见列、列顺序或结果变化后需重新选择；选区不跨页、不跨标签保留。矩形选区与行号旁的勾选行独立。

### 复制选中行

勾选当前页的行后，点「复制选中行」。剪贴板包含表头和可见数据列，按网格的行序和当前可见列序提供制表符分隔文本。已暂存的单元格修改按点击时的显示值复制。含制表符、换行或双引号的字段会用双引号包住，字段内的双引号会写成两个。`NULL` 复制为空字段。复制前会获取被截断字段的全文，读取失败时保留原剪贴板。

### MySQL 更新 SQL 预览

编辑 InnoDB 表后点击「应用修改」，可先查看连接、目标表、计划修改的行数、带主键条件的 `UPDATE` 及绑定参数。点击「取消」会保留草稿。点击「应用修改」会按确认的计划执行，随后可提交或回滚。若计划发生变化，请重新预览。

翻页、调整每页行数、刷新、排序筛选或关闭标签时，若选择「应用修改」，也会先显示这份预览；取消预览会中止原操作，保留草稿和结果。新增行或删除行之前若需应用已有草稿，同样先预览 UPDATE。

点击「提交」，或离开连接时选择「应用并提交」，会一次列出同连接所有标签的 UPDATE 草稿，分别显示目标表、行数、SQL 和参数，并说明已有未提交事务。确认会提交该连接的全部事务，包括此前已应用的插入、删除或 SQL 写入；其他连接不受影响。取消不会新增写入，也不会回滚已有事务。正在编辑的单元格或新增行需先保存或取消表单。

确认前草稿、结果或事务状态发生变化时会拒绝执行，需重新预览。多表应用途中失败时不会继续提交：已经应用的修改需结合当前事务状态处理，未应用成功的草稿保留。如果 MySQL 明确因死锁回滚整个事务，本轮仍有效标签的草稿会保留或恢复；此前已应用的事务修改不属于本轮草稿。应用或提交成功后仅刷新失败时，会明确提示已完成的写入阶段。提交报错或结果未知时应先核对数据库状态，不要直接重复提交。

### MySQL 批量粘贴

从 Excel 复制一块不含表头的数据，选中网格的起始单元格后按 `Ctrl+V`。粘贴区域必须在当前页内。遇到格式错误、目标列只读或数值无法放入目标列，整批退回并提示位置。

文本列里的空白单元格按空字符串暂存。未加双引号的 `\N` 表示数据库 `NULL`，`"\N"` 表示文本原值。粘贴成功后，点「应用修改」预览 SQL，再提交或回滚事务。

## SQL 标签和草稿

点「新建 SQL 标签」即可在当前连接下另开一份草稿。每个标签保存自己的 SQL 和连接，重启后恢复仍打开的标签。打开 SQL 文件、载入历史或收藏时，新建标签保留当前草稿。关闭有内容的标签前会确认。

用「SQL 连接」切换到相应连接的标签。对象树和结果标签各自保留其上下文。执行按钮和参数弹窗使用发起时的 SQL 标签和连接。若连接已关闭、更新或移除，先确认目标并重新发起查询。

MySQL 标签显示连接配置里的默认库。使用不同库时可分别建立连接。手动执行 `USE` 会改变该连接的会话默认库，并影响同连接的其他标签。

首次打开会恢复旧版按连接保存的草稿。格式未知或无法写入时，工作台提示当前会话的草稿保留在内存中。

## 和事务的关系

- 每一组编辑 / 执行都归属到**发起它的那条连接**。
- 事务是**连接级**的：同一连接的所有标签共享事务状态，不同连接之间互相独立。
- 点「提交」会先应用同连接所有标签的未应用修改，再提交该连接事务；MySQL 会先统一预览并确认。点「回滚」会放弃同连接所有标签的本地修改及未提交事务。

（对应验证：`test:gui-mutation-transaction`、`test:gui-sql-transaction`。）
