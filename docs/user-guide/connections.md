# 连接管理

本页说明怎么新建、编辑、断开和删除数据库连接，以及密码是怎么保存的。

---

## 新建连接

点左上角的「新建连接」，选择数据库类型，填写对应字段。

目前支持四种，填写的字段不同：

### SQLite

只需要一个**文件路径**，直接选一个 `.db` / `.sqlite` 文件即可。

SQLite 是单文件数据库，没有主机、端口、用户名这些概念。

### PostgreSQL

| 字段 | 说明 |
|---|---|
| 主机 | 默认 `127.0.0.1` |
| 端口 | 默认 `5432` |
| 数据库 | 要连的库名 |
| 用户名 | 默认 `postgres` |
| 密码 | 可选，见下文「密码是怎么存的」 |
| SSL 模式 | 可选，见下文「SSL / TLS」 |
| SSH 隧道 | 可选，见下文「SSH 隧道」 |

### MySQL / MariaDB（Beta）

| 字段 | 说明 |
|---|---|
| 主机 | 默认 `127.0.0.1` |
| 端口 | 默认 `3306` |
| 数据库 | 要连的库名（MySQL 用 database 作命名空间，等价于其它方言的 schema） |
| 用户名 | 默认 `root` |
| 密码 | 可选，见下文「密码是怎么存的」 |
| SSL / TLS | 可选，支持 disable / require / verify-ca / verify-full |
| SSH 隧道 | 可选，与 PostgreSQL 共用主机指纹确认 |

> MySQL / MariaDB 已支持连接、目录和表结构浏览、分页查询、参数绑定（`?`）、EXPLAIN、
> `KILL QUERY` 取消、网格编辑、插入/删除、事务、完整值读取、CSV/JSON/JSONL/SQL INSERT
> 导出、CSV 批量导入、结构/数据比较和常用 DDL。CHECK/触发器、视图、例程、外键动作、
> SSL/TLS 与 SSH 也会按服务端版本和连接配置启用或明确提示边界。
> 具体能力与版本限制见[数据库支持矩阵](../support/database-matrix.md)。
>
> 已知边界：SQL 窗口里手写的 `BEGIN/COMMIT` 不由驱动的事务跟踪覆盖；MySQL DDL 会隐式
> 提交事务，未提交编辑时需要先提交或回滚；完整 GUI 导入链路仍待补一条真库 GUI 用例。

### Redis（只读浏览）

| 字段 | 说明 |
|---|---|
| 主机 / 端口 | 默认 `127.0.0.1:6379` |
| 用户名 | ACL 用户名，可空 |
| 密码 | 可空 |
| TLS | 需要时勾选 |
| 键过滤 | 对应 `SCAN MATCH`，默认 `*` |

Redis 只做**浏览**，不能写入或编辑。

### Kafka（只读浏览）

| 字段 | 说明 |
|---|---|
| brokers | 以逗号分隔的 `host:port` 列表 |
| Client ID | 默认 `dbstudio` |
| SSL / SASL | 需要时配置 |

Kafka 同样只做**浏览**，不能发送消息。

## 密码是怎么存的

密码**不会明文落盘**。它用操作系统的安全存储加密（Electron `safeStorage`）。

这意味着：

- **正常情况下**（macOS、Windows、有桌面密钥服务的 Linux），密码加密保存，下次直接连上，不用重输。
- **少数环境**（没有桌面密钥服务的 Linux，例如某些服务器或容器）安全存储不可用。这时会**明确提示"密码不会被保存，请每次连接时手动输入"**，而不是假装存了。

看到这类提示不用慌，它是在如实告诉你：这个环境下密码没存，下次要重输。**数据不会因此受损**。

> 如果你在这个环境里断开再重连，会发现需要重新输入密码——这是预期行为，不是 bug。

## 测试连接

新建或编辑连接时，可以先点「测试连接」。它会**真的建立一条连接再关掉**，而不是只检查字段格式。

所以"测试通过"意味着网络、认证、权限都是真的通的，不会出现"测试通过但真连不上"。

## 编辑、断开、删除

在左侧连接树里，每个连接有三种操作：

- **编辑连接**：改配置或改密码。如果这条连接当时是连着的，保存后会自动重连让新配置生效。
- **断开**：关闭会话但**保留连接配置**。想临时断开又不想丢掉配置时用它。
- **删除连接**：从列表里移除。会**弹确认框**，不会误删。

如果这条连接上有**未提交的事务**，断开或删除前会先拦下来提醒你——不会把你的未提交修改悄悄丢掉。

## SSL / TLS

### PostgreSQL

不要指望这里直接填 `sslmode` 字符串就完事——那样容易把"要求加密"错配成"允许明文"。

这里提供的是明确的选项：

- **ssl 模式**：控制是否/如何加密
- **根证书**：校验服务器证书用

配了证书校验时，**证书不对会真的被拒绝**，不会降级成不加密继续连。这是有测试覆盖的（`test:postgres-ssl`）。

### MySQL / MariaDB

支持 `disable`、`require`、`verify-ca` 和 `verify-full`。启用证书校验时，服务端证书不匹配会拒绝连接，不会静默回退到明文。

### Redis / Kafka

两者都支持 TLS（Redis 勾选 TLS，Kafka 配置 SSL/SASL）。按你的服务端实际配置启用即可。

## SSH 隧道

PostgreSQL 与 MySQL / MariaDB 支持 SSH 隧道。

当数据库只能通过跳板机访问时，配置 SSH 主机、端口、用户名和认证方式（口令或私钥），连接会先建 SSH 隧道再连数据库。

关于主机指纹：这里**不做 TOFU（首次连接自动信任）**。第一次连某台 SSH 主机时，需要你确认它的指纹，之后会记住。这样能防止中间人冒充。

## 常见问题

**Q：断开后重连要我重新输密码？**

A：如果你的环境不支持安全存储（见上文），是的。这是如实提示的结果。

**Q：删除连接会不会把数据库里的数据删掉？**

A：不会。删除连接只是从客户端列表里移除，不碰数据库本身。

**Q：有未提交事务时为什么断不开？**

A：防止丢数据。先提交或回滚，再断开。
