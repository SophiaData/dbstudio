# 元数据、ER 图与结构比较

本页说明怎么查看表结构、看表间关系，以及比较两个库的结构差异。

---

## 表结构元数据

选中一张表，可以看到它的结构：

- **列**：名称、类型、是否可空、默认值、是否自增/生成列、是否主键
- **主键**
- **外键**：指向哪张表、哪些列
- **索引**：包含哪些列、是否唯一、有无条件（部分索引）
- **唯一约束**
- **CHECK 约束**
- **触发器**

### 关于"读不到"和"确实没有"

这俩是不同的，界面会区分：

- **读不到**（比如驱动不支持、或权限不足）：显示为"未知"
- **确实没有**：显示为"没有"

不会把"读不到"伪装成"没有"——否则你会以为某张表没有外键，实际只是没读到。

### 各数据库的差异

SQLite 和 PostgreSQL 都能读出上述全部元数据（有 `test:metadata-contract`、`test:sqlite-metadata`、`test:postgresql-metadata` 覆盖）。Redis / Kafka 没有表结构这个概念。

## ER 图

点「ER 图」可以把当前 schema 里的表画成实体关系图。

### 关系从哪来

关系线**只来自数据库中真实存在的外键约束**。没有外键就不会有线——**不做基于命名约定的猜测**。

这是刻意的：猜出来的"关系"看起来很像真的，但一旦你按它去理解数据模型，就会被误导。宁可不画，也不画错的。

### 能做什么

- **拖拽布局**：拖动表框，关系线端点会跟着走
- **布局自动保存**：下次打开恢复你摆好的位置
- **选中高亮**：点一张表，与它相关的关系会高亮
- **导出 SVG**：把图导出成矢量图，可以放进文档

（对应验证：`test:er-relations`、`test:er-layout`、`test:gui-er-relations`、`test:gui-er-selection-export`。）

## 结构比较

比较**两个数据库的结构**，生成同步 SQL。

### 比较什么

- **表**：新增、删除、列变化、索引、外键、约束
- **视图**：新增、删除、**定义变化**（能看出视图的 SQL 逻辑改了没有）
- **例程**（PostgreSQL）：函数与存储过程的新增、删除、修改；支持函数重载（同名不同参数视为不同对象）

### 生成的 SQL 只生成、不执行

比较结果会列出需要的 `CREATE` / `DROP` / `ALTER` 语句，但**不会自动执行**。要不要执行、怎么执行，由你决定。

### 危险语句会被标记

删除表、删除列、加非空约束这类**会丢数据**的语句会被明确标红，要求二次确认。

### 定义读不到时不猜

如果某个视图或例程的定义没读到（权限不足等），比较结果会**明确标注"定义未捕获"并告警**，而不是假装"没有差异"。因为"看起来一致"和"真的比较过"是两回事。

（对应验证：`test:structure-compare`、`test:compare-live`、`test:gui-compare`。）

### 物化视图

暂不参与结构比较。物化视图是"有数据的物化结果"，刷新语义和普通视图不同，混在一起比会误导。

## 数据比较

比较**两张表的数据**，给出 `INSERT` / `UPDATE` / `DELETE` 的行数和具体 SQL。

### 需要可靠的比较键

数据比较需要能唯一确定每一行的键（通常是主键）。**没有可靠比较键时会拒绝比较**，而不是随便拿一列去比——那样会给出错误的对账结果。

### 长文本按全文比

超长文本在界面上是折叠显示的，但比较时按**全文**比对，不是拿截断后的预览去比。否则两段预览相同、实际不同的长文本会被误判为"一致"。

### BLOB 不参与比较

二进制内容（BLOB 列）**不参与数据比较**。二进制的"相等"判断不可靠，我们不猜。

（对应验证：`test:data-compare`、`test:compare-live`、`test:gui-compare`。）

---

## 跨数据库比较

结构比较和数据比较都**只支持同一种数据库之间**（SQLite ↔ SQLite，PostgreSQL ↔ PostgreSQL）。

跨数据库比较（比如 SQLite ↔ PostgreSQL）会被**明确拒绝**，因为不同数据库的类型系统、约束语义差异很大，硬比会产出一堆似是而非的差异。
