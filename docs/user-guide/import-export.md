# 导入与导出

本页说明怎么把数据导出来、怎么把 CSV 导进去，以及各自的边界。

---

## 导出

### 支持的格式

| 格式 | 说明 |
|---|---|
| **CSV** | 逗号分隔，通用，能用 Excel / 表格软件打开 |
| **JSON** | 整个结果是**一个 JSON 数组**，适合脚本处理 |
| **JSONL** | 每行一个 JSON 对象（JSON Lines），适合流式处理大文件 |
| **SQL INSERT** | 生成 `INSERT` 语句，可拿去别的库执行 |

### 导出范围

- 「全部」导出的是**当前查询的全部结果**，不受网格已经加载了多少行限制。
- 导出采用**分批读取**：每次读完一批就写入并丢弃，所以**内存占用和总行数无关**，百万行也不会把内存吃满。

### 一个重要限制：不是时间点快照

导出是分批读取的，**不保证是某一时刻的快照**。如果导出过程中底层表正在被其他人修改，不同批次之间可能出现重复行或遗漏行。

需要严格一致的数据时，请在导出期间停止写入，或先在一个事务/只读副本里冻结数据。

### 内容不完整时会拒绝导出

如果结果里有被截断的超长字段，导出的文件就是**错的**（用户以为导全了，其实是预览）。所以遇到这种情况会**直接拒绝导出并说明是哪个列、哪一行**，而不是悄悄产出一个残缺的文件。

（对应验证：`test:gui-export-integrity`。）

## CSV 导入

### 导入流程

导入分几步，每一步都能看到结果再决定：

1. **选文件**：选一个 CSV 文件。
2. **识别编码**：自动识别文本编码。识别错了可以手动改，改错会明确报"编码无效"，不会产出乱码数据。
3. **选分隔符**：默认逗号。分隔符必须是单个字符，且不能是引号或换行。
4. **列映射与类型**：决定每一列写到哪个字段、按什么类型解析。
5. **校验与预览**：逐行校验，错误会定位到具体行。
6. **执行导入**：分批写入。

解析遵循 RFC 4180：支持双引号转义、引号内的换行和分隔符——所以字段里带逗号、带换行的数据不会把行切错。

### 失败的导入会回滚

导入不是"尽力而为、错一半留一半"。**导入失败会回滚本次导入**，不会在表里留下半截数据。

（对应验证：`test:import-validation`、`test:import-task`、`test:import-pg-transaction-state`。）

### 只读数据源不能导入

Redis / Kafka 是只读浏览，没有"导入"这个概念。

## 常见问题

**Q：导出的 CSV 用 Excel 打开是乱码？**

A：确认编码。导出默认按 UTF-8。Excel 有时需要 BOM 才能正确识别 UTF-8，可以用文本编辑器另存或改用 JSON。

**Q：导到一半失败了，表里会不会有脏数据？**

A：不会。导入失败会回滚本次导入。已有的数据不受影响。

**Q：导入时提示某行错误？**

A：定位到具体行。常见原因是该行某个字段无法按选定类型解析，或者必填列为空。改好数据或调整列映射后重试。

**Q：能从 MySQL / MariaDB 导入吗？**

A：可以。MySQL / MariaDB 的 CSV 批量导入和导出链路已覆盖；CHECK 约束版本、DDL 隐式提交等边界见[数据库支持矩阵](../support/database-matrix.md)。完整 GUI 导入向导仍需要真库 GUI 回归。
