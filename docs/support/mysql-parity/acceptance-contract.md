# MySQL 对标体验与真实验收约定

日期：2026-11-07。状态：目标已建立，差距核对与实施准备中；尚未达到对标或生产放行标准。

用户要求：MySQL 的使用体验对标 `t8y2/dbx` 和 DBeaver，必须真实验收。此前针对核心范围估算的 11 月 13 日不自动适用于此次更大范围，也不是生产达标保证。

## 参考范围与证据等级

- 参考项目固定为 `https://github.com/t8y2/dbx` 与 DBeaver Community；参考提交、版本、功能所属版本和官方出处记录在 `reference-baseline.md`。付费版本独有能力必须明示，不能误称 Community 已有。
- 对标按同一任务能否完成、操作步骤、上下文保留、错误反馈、数据正确性与耗时评估，不要求复制外观。dbx 独有的结构/数据比较等能力单列保留，不因 DBeaver Community 没有就自动删去。
- 参考文档/源码、dbstudio 源码、纯内存回归、真实驱动、真实桌面 DOM 操作分别记录；前四项不能替代最后一项。参考产品尚未亲自运行的交互必须标“官方资料，操作待测”，不能称实际体验已相同。
- 初始真实版本矩阵包括 MySQL 8.0 与 8.4 LTS，分别冻结镜像 digest、实际 `VERSION()`、sql_mode、字符集和时区。MySQL 5.7 兼容性作为明确未验证行保留；MariaDB 不冒充 MySQL。完成某一版本不能自动提升其他版本状态。
- macOS arm64 和 Windows x64 分别给出实际证据。真实 Tauri 测试构建可以隔离配置、WebView 数据和合成凭据；不得改变业务后端或以 mock 代替 MySQL。此证据不自动证明正式安装包/平台系统交互通过。

## 数据与隔离要求

1. 每轮新建带唯一 run ID 的 MySQL 容器/库和普通测试对象，账号只作用于专用实例；不读取或写入生产库。文件、容器和数据保留，不执行删除清理。
2. 真实 UI 使用独立应用配置、禁旧配置导入、独立 WebView storage；凭据测试用独立合成 OS keyring namespace。内存 SecretStore 只能证明当前进程，不能计为凭据重启持久化通过。
3. 实际连接密码不出现在命令行、报告、截图或日志；工具只使用环境变量名、固定错误分类及合成结果计数。公开截图前审核只含合成信息。
4. 对事务可见性、写入精度、DDL 结果和导入行数，使用独立观察连接/事务核对，不能仅相信 UI 状态或用相同转换路径自证。
5. 每份证据记录源码 HEAD、dirty 改动摘要/哈希、构建特征、测试钩子范围和 MySQL 镜像 digest。基线常量不能替代实际来源核对。

## 放行条件

- 核心共同任务及用户要求的必选对标项全部通过；单方高级项、版本和平台差距明确，不得借重分类绕过目标。
- 数据正确性、精度、写入目标、事务状态、取消与恢复没有未解决 P0/P1；出现丢稿、错误写入或事务误报立即停止放行。
- 性能门槛在固定设备/数据、参考工具同任务测量后确定，分别保留预热/冷启动、数据库耗时、UI 可见耗时与全应用资源。未取得参考实测前不能声称性能相当。
- 真实 MySQL 驱动和实际 DOM 用户动作必须双层验证，有证据可复核；模拟测试仅作补充。
- 8 小时稳定性、候选构建验证及非实现者独立 review 完成后才可写“达到所声明范围的生产门槛”。报告中的失败/受阻行保持可见。

## 执行顺序

先完成参考基线、驱动/桌面差距与隔离验收基座设计，再建立最短真实查询链。随后按数据正确性和高频任务优先补齐，逐项红色复现 → 最小实现 → 回归 → 真实 UI 与数据库回读 → 独立 review。任务状态写入共享团队任务板，具体实施计划存入 `docs/superpowers/plans/`；没有证据时保持目标未完成。
