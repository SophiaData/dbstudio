## 场景结果

### ref:M01 连接管理

**步骤**：新建连接 → 选择 MySQL → 填主机 `127.0.0.1`、端口 `13306`、用户、口令、库 `testdb` → 点「测试」→ 点「保存并连接」。

**观察**：
- 表单字段：URL（可选）、名称、类型、颜色、主机+端口、用户名、口令（带"保存密码"勾选）、数据库、数据字符集（只读）、连接参数、数据库信息、备注。
- 点「测试」后出现状态 `连接成功`，**未显示耗时或版本号**。
- 连接建立后连接名自动生成为 `MySQL_elxh`，列表显示 `127.0.0.1:13306`，概览计数"连接 1 / 已连接 1 / 数据库类型 1"。

**独立回读**：连接在数据库侧可见（同一容器、同一账号）。

**未测边界**：未验证"测试"失败时的错误呈现（错误口令、错误端口）；未验证重启后口令是否保留；未验证 SSH/TLS 组合。

### ref:M03 对象浏览

**步骤**：在左侧树点连接展开箭头 → 展开 `testdb` → 展开 `表` → 展开表 `g2`。

**观察**：
- 连接下第一层：`testdb`（标"默认库"）、`用户与权限`。
- `testdb` 下分类：`表`、`视图`、`存储过程`、`函数`、`触发器`、`事件`、`查询`、`用户与权限`。
- `表` 后带计数 `3`，列出 `g2`、`part_demo`、`pt_probe`。
- 表 `g2` 展开后子节点：`字段`、`索引`、`外键`、`触发器`。

**独立回读**：`SELECT COUNT(*) FROM information_schema.TABLES WHERE TABLE_SCHEMA='testdb' AND TABLE_TYPE='BASE TABLE'` 返回 **3**，与树内计数一致；表名逐一对应。

**未测边界**：未展开视图/存储过程/函数/触发器/事件的实际内容；未验证同名表在两连接间切换是否串上下文；未测刷新行为。

### ref:M04 SQL 执行

**步骤**：点欢迎页「新建查询」→ 编辑器出现，顶部显示连接与库上下文 → 输入 `SELECT 42 AS from_probe;` → 点「执行全部 SQL」。

**观察**：
- 编辑器为 CodeMirror，工具条含：执行全部 SQL、在新结果标签页执行、Autotrace（会执行查询）、切换行注释、全部折叠/展开、使用小写 SQL 关键字、自动换行、SQL 语义诊断（默认关闭）、INSERT 列名提示（默认开启）。
- 结果区：`#  from_probe bigint`、`共 1 行 （总计 1 行）`、`1 列`、**`6 ms`**。
- 结果区底部显示实际执行的 SQL：`SELECT 42 AS from_probe LIMIT 100;`，并可「复制 SQL」。
- 结果区提供：字段筛选、跳转列、数据表/摘要/图表/消息/执行计划 五个页签、保存结果、只读结果、刷新、自动刷新、排序、导出、「查询耗时详情」、「加载全部并转到末行」。

**独立回读**：`SELECT 42` 的值即 42，无需额外核对。

**未测边界**：未测部分选中执行、参数绑定、多语句、错误语句的表现；未测「查询耗时详情」展开后的分段数据。

### ref:M07 结果分页

**步骤**：在同一编辑器执行 `WITH RECURSIVE seq AS (SELECT 1 AS n UNION ALL SELECT n + 1 FROM seq WHERE n < 500) SELECT n FROM seq;`。

**观察**：
- 结果区：`共 100 行 （统计总行数）`、`1 列`、**`23 ms`**、`100 行/页`。
- 实际执行 SQL 显示为 `... LIMIT 100`，即可见页由 LIMIT 驱动。
- 「统计总行数」为可点击控件，说明总行数按需统计而非默认全量。

**独立回读**：同一递归 CTE 在数据库侧 `COUNT(*)` 返回 **500**。

**与 dbstudio 差异**：dbstudio 固定 200 行/页、仅前后翻页、不提供"加载全部并转到末行"，也不在结果区显示带 LIMIT 的实际 SQL。dbx 的页大小可切、总行数按需统计、并支持一次加载到末行。

**未测边界**：未测 10 万/100 万行的表现；未测跳页与深度滚动；23 ms 是本机 loopback 单次取页耗时，不是性能基准。

### ref:M15 表结构

**步骤**：同 M03 的表展开路径。

**观察**：表节点下直接给出 `字段`、`索引`、`外键`、`触发器` 四类子节点，均为树内可直接展开的一级入口。

**与 dbstudio 差异**：dbstudio 的表结构、索引、外键在主区域表格中呈现，分区作为表子节点；dbx 把四类对象都做成树内一级子节点，导航层级更浅。

**未测边界**：未展开这四类子节点核对内容；未测通过界面修改索引/字段的流程；未测 DDL 生成与审阅。

## 与本次结论的关系

这 5 个场景使[覆盖映射](coverage-map.md) 中 M01、M03、M04、M07、M15 五行具备了 dbx 同任务实测记录，达到契约要求的"参考未实测"之上的可比较状态。仍不构成"体验已对齐"的结论：

- 只覆盖 5 个任务，契约共 23 个；
- 操作通过浏览器合成点击完成，不是 OS 级输入；
- 未做 dbx 与 dbstudio 的逐步耗时对比（两侧环境与构建不同，直接比较数字无意义）；
- 未测边界如各节所列，不能由已观察项外推。

## 复现方式

1. 下载 `dbx-web_0.6.71_x86_64-browser-static.zip` 并解压；
2. 设 `DBX_PORT`、`DBX_DATA_DIR`、`DBX_DISABLE_PASSWORD=1` 后运行 `dbx-web.exe`；
3. 浏览器打开 `http://127.0.0.1:<DBX_PORT>/`；
4. 按上述步骤连接同一 MySQL 实例操作。数据目录与端口均独立，不触碰其他 dbx 实例。
