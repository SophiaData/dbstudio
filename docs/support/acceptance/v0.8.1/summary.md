## 用户调整后的业务优先结果

后续按用户纠正，将数据库管理业务置于安装环境之前，已复现并修复六项源码问题：迟到完整值覆盖编辑草稿、取消新增仍关闭表单、应用修改后翻页失败丢位置、SQL 错误后事务缓存不刷新、取消请求未接受却提示已请求，以及自动改为 CSV 后沿用 `.sql` 文件名。新增 28 个业务回归，加上原有 18 个模型回归，共 46 项通过；类型检查和 135 项清单检查通过，改动已完成独立只读复核。详见上方业务报告的证据、测量层级及限制。

修复位于当前源码，尚未进入已发布的 v0.8.1 安装包。下列环境条件仅用于后置的平台验收，不是继续数据库业务验证和修复的前置条件。

## 首轮结论与后置平台验收

首轮原生层证据支持：正式包静态检查、68 项原生安全回归、2 项真实 NoSQL 安全连接，以及隔离核心的查询、分页、导入导出和短循环取得通过结果。该阶段未发现需修改 Rust 核心的已确认缺陷；后续 Vue/工作台业务层已发现并修复上述六项问题，两阶段不能混为“没有业务缺陷”。Mac bundle 资源签名异常已复现，其实际启动影响仍待验证。不能据此写“双平台安装验收完成”或“成熟稳定”。

后置平台验收所需的最小条件：

1. 一个独立干净的 macOS GUI 测试账户或测试系统，能够启动正式 DMG 中的应用并由操作者处理系统提示。该条件用于继续 Mac I/F 用例及签名异常的启动影响验证；不能使用当前真实配置账户代替。
2. 一个明确可用的 Windows 11 x64 干净测试会话。先完成 I02—I09，再执行 F01—F13，保留原生保存框、剪贴板和凭据交互证据。
3. SQL TLS/SSH 夹具需要正常、明确允许的 Docker build 条件；内存测量需要允许采集测试应用自身进程组。当前不修改系统策略或换入口规避拒绝。
4. 安装和核心业务通过后，另行实际执行 8 小时观察及观察后的操作；本轮短执行与中断期间的自然经过时间均不算长期运行证据。

卸载、删除清理及包含实际 DELETE/DROP 的用例继续受现有规则限制，保持未验证。剩余条件未补齐前，整体计划保持部分完成。
