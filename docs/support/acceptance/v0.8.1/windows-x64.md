用 Python 标准库只读计算指定文件的 SHA-256，并按 DOS/PE 头中的偏移解析 COFF、Optional Header 和 Security Directory。未通过运行 EXE 获取信息。

| 检查 | 实际证据 | 状态与结论边界 |
| --- | --- | --- |
| 文件大小 | 5,056,090 bytes | 已读取指定文件 |
| SHA-256 | `41403e3117aaade4dd8c9b9eb433684cb2bc925da8a489e89d726e1c6e9da292` | 与计划及任务指定值完全一致 |
| DOS/PE 标识 | `MZ`、`PE\0\0` | 文件具备可解析 PE 头；不证明可安装或启动 |
| 外层 COFF Machine | `0x014c`（I386） | 仅指安装引导程序的 x86 架构 |
| Optional Header / Sections | `0x010b`（PE32）；5 sections | 外层 PE 结构信息 |
| 嵌入证书表 | Security Directory file offset = `0`，size = `0` | 本文件未携带 PE 嵌入式 Authenticode 证书表；没有完成 Windows 信任链、目录签名或 SmartScreen 检查 |
| 内部应用架构、版本和来源 | 未提取 payload，未执行已安装应用 | 未验证；文件名和任务基线不替代内部应用元数据证据 |

NSIS 外层引导程序可以是 x86。**不能据 `0x014c` 将 x64 payload 判为架构不匹配，也不能反向据文件名确认 payload 架构。** 本轮哈希一致只证明本地文件与指定预期文件一致；未独立复核发布来源证明或内嵌应用版本。

未生成合成数据，也未准备 Windows 独立账户。T0 的版本目标及安装包哈希已登记；Windows 环境隔离、测试数据就绪和实机环境信息仍未完成，因此 T0 整体不计通过。

## 最短后续执行条件

1. 提供一个明确获准使用的 **Windows 11 x64 干净测试账户或干净系统及桌面会话**，并记录 Windows 版本、CPU 架构和内存。若现有环境为 Windows arm64，不能直接把它计为本计划的 x64 环境验收。
2. 在该环境准备同一发布 EXE，使用 `Get-FileHash -Algorithm SHA256` 再次核对上述哈希。先确认测试账户没有既有 dbstudio 配置或安装数据；发现既有数据时换干净账户，不覆盖、不清理个人数据。
3. 在隔离位置准备计划附录 A 的合成 SQLite/CSV/比较数据：805 行及必要的 100000 行库、long_values、small.csv、large.csv、duplicate-key.csv 和比较库。各导入用例使用各自空目标，导出选择新文件；不通过删除既有数据重置用例。
4. 人工在 Windows 完成 I02–I09，再在已安装应用逐项执行 F01–F13。系统安全确认、可能的凭据提示、原生文件对话框、剪贴板和正常退出需操作者观察。人工只保留脱敏提示、版本、用例 ID、计数和耗时，不采集凭据或其他进程信息。
5. I04 及 PostgreSQL/MySQL 扩展场景需要专用服务，由操作者输入合成凭据。无服务的项目继续标受阻；无凭据提示的平台只能在实际观察后判“不适用”。

本报告完成的是静态核查与环境缺口记录。I02–I09 和 F01–F13 共 **21 项实机验收受阻**；未发现经 Windows 运行复现的产品缺陷，也没有 Windows 可用性通过结论。
