# dbstudio 健康治理执行计划

## 1. 目标、角色与事实边界

目标：逐项核对健康审查发现与当前代码，修复可确定缺陷，验证每个受影响表面，交付可追溯补丁、实际运行证据和明确的剩余决策。

- 任务总管：主代理。负责拆解、优先级、依赖、范围、证据核验、独立审查、失败分流与最终放行。
- 执行者：DeepSeek。领取一个就绪任务，阅读实际代码，复现、最小修复、运行验证、回报结果。不得自行扩大任务、改验收口径或宣布整体完成。
- 独立审查者：由任务总管另外指派，只读审查；实现者不能同时为自己的实现放行。
- 用户：仅裁决产品契约、维护范围及需要新增授权的动作。代码事实和现有行为由执行者自行查证。

事实源：[健康审查台账](project-health-audit.md)。台账的 F/U/D 编号是问题身份，不是当前修复状态。章节标题、旧行号及“本轮已修”均须与当前工作树重新对照。报告所列历史测试结果不能直接当作本次验收证据。

本计划是按依赖领取的工作计划，不设定时触发，也不默认启动全部执行者。不提交、不推送、不发布、不执行生产写入。

## 2. 执行约束

1. 不新建任何目录。新文件只放已经存在且属于本任务的目录；先复用现有测试与文档。备份父目录不存在时停止该写入并交总管处理，不能以备份要求为由自行建目录。
2. 不运行 rm、unlink、rmdir、清空输出等删除路径。执行测试前检查脚本及其直接启动器；不能安全执行时保留测试产物或换用不删除的等价入口，并说明覆盖边界。
3. 不查看、打印或复制真实凭据、Cookie、认证头和业务隐私输出。连接信息仅使用环境变量名；真实数据库测试只能使用隔离的合成数据。
4. 本地现有未提交改动不重置、不覆盖、不自动归属为执行者成果。先核对再增量修改。
5. 每项任务先报拟修改文件和影响面，再 read、备份、edit。只修本项直接问题，不顺手重构。
6. 多执行者共享工作树时按文件分配唯一写入者。原生驱动、比较器、SDK、UI、报告分别串行，禁止重叠文件并行编辑。
7. 不为假绿而放宽断言、改成任意异常通过、忽略失败或更新错误的期望值。必须先确认预期契约。
8. 真实数据库缺失时可以完成纯逻辑或编译证据，但真实事务、锁、TLS、SSH等验收保持“待运行”，不能用 fake 代替。

## 3. 状态机与回报格式

任务状态：待领取 → 取证中 → 已复现 → 修复中 → 待验收 → 独立审查 → 通过。例外状态为待决策、环境受阻、审查失败。

DeepSeek 只能提交“待验收”，由总管核对实际证据后推进。此前已修项仍从取证开始，避免重复改动。

每次回报使用以下字段：

```text
任务 ID / 关联发现：
起始 commit / 当前分支 / 受影响文件的起始状态：
确认的触发条件与消费入口：
修复前复现命令 / 实际输出：
修改文件与最小行为差异：
修复后命令 / 退出码 / passed、failed、ignored、skipped：
证据保存位置或可回读的任务运行记录：
实际覆盖表面：
刻意未验及原因：
剩余风险 / 请求总管裁决的唯一问题：
```

不以自述“已验证”替代输出；记录测试名称与跳过原因。每项最后回读 diff 和正文，核对无额外改动。

## 4. 分阶段执行顺序

| 阶段 | 工作包 | 前置 | 放行条件 |
| --- | --- | --- | --- |
| A 基线与台账 | P00–P02 | 无 | 工作树归属明确、修复状态可追踪、验证入口安全 |
| B 已有补丁复核 | P03–P06 | A | 现有修改有新鲜证据，未验证部分明确保留 |
| C 高风险剩余项 | P07–P10 | B及相应契约确定 | 不存在隐藏写入、未知事务状态误报或误导同步计划 |
| D 契约与覆盖补齐 | P11–P15 | 相应前置 | 解析、交换、测试、文档、阅读覆盖一致 |
| E 集成与放行 | P16–P18 | 所有实施项结束 | 最终diff、双轴审查、统一门禁、三栏报告齐全 |

A 必须先做。B 内可按文件互斥并行。C 的原生驱动与已有驱动修复复核串行；比较器契约先确定再实施；D 中涉及同文件的工作等待前项。不能因某一环境受阻而停止其它互不依赖的工作。

## 5. 任务卡

### P00 · P0 · 冻结取证基线与工作树归属

- 范围：Git 元信息、当前 diff、现有任务板及报告；不读取备份内容或敏感 evidence JSON。
- 步骤：确认实际 cwd、分支、HEAD；列出已跟踪修改和未跟踪交付物；核对中断执行者是否留下半成品；将每个文件归到问题编号或标记归属待确认。
- 产出：在现有台账记录基线、文件负责人和不可覆盖项；旧任务板“进行中”不得直接当作执行者仍在运行。
- 验收：所有本次补丁都有对应问题；无无关修改被重置；未知归属项由总管决定保留方式。

### P01 · P0 · 重建可用的问题状态索引

- 范围：健康台账全部 F01–F14、U01–U46、D01–D17。
- 步骤：逐项对当前代码和测试；使用“未修 / 代码已修待验 / 已验的具体表面 / 待真实环境 / 待决策”字段；拆开修复状态与证据状态；重复项保留映射，不丢独立风险。
- 验收：不存在“未修章节却被默认视为未修”的歧义；每个编号有当前状态、下一任务、证据位置。旧行号失效时更新直接链接。

### P02 · P0 · 验证入口与环境预检

- 范围：package scripts、计划执行的启动器、Rust/Node工具位置及已有测试服务可用性。
- 步骤：确认 cargo/rustc/node/pnpm 的实际路径及版本；检查目标命令是否删除文件、创建目录或触碰真实用户配置；确认真实库、Docker、浏览器等是否确实存在，不自行安装或启动新服务。
- 验收：形成“可直接执行 / 需要安全入口 / 环境受阻”命令清单。没有真实环境的任务明确保留，不阻断纯逻辑任务。不得为检查环境输出认证信息。

### P03 · P1 · 原生数据库修复证据复核

- 关联：F10/F11，U01–U11，U18，D10/D11。
- 范围：Rust core、drivers、protocol及直接测试；此工作包独占相关源码写入。
- 步骤：检查事务保存点、失败导入锁定、批次预校验、RETURNING解码失败回滚、1213状态协调、快照预算、Redis键字节身份、UTF-16边界、LIMIT+1、生成列过滤、终态任务回收。已有实现正确时不重复改写。
- 验证：安全前提下执行 locked check/test；分别记录每个target与ignored。SQLite以真实临时库测FAIL/ROLLBACK与此前事务保留；PG/MySQL/Redis的fake证据与真服务证据分开。
- 验收：每个问题有针对性测试而非只看总数；生成列/主键/精度处理无隐式降级；真实服务未测项仍开放。

### P04 · P1 · UI已有修复复核

- 关联：F03–F06，U12–U17。
- 范围：原生组件、workbench、result-export、sql-editor-model及UI回归。
- 步骤：验证切连接清表、比较SQL分隔、DECIMAL精确文本、DDL清游标、可写列投影、连接内补全、排序取消/失败恢复、NULL BLOB只读、插入成功但刷新失败禁止重复写、MySQL文本hex。
- 验证：typecheck及真实组件/模板回归；检查全部成功、取消、失败入口；有桌面环境时补代表性GUI交互，不另起替代服务冒充当前产品。
- 验收：IPC目标与表身份一致、长小数不舍入、刷新失败不重复insert；无DOM测试只能验组件逻辑，不得声称桌面端到端。

### P05 · P1 · HTTP、存储、SDK与旧界面已有修复复核

- 关联：F01/F02/F12，U19/U20/U29/U30/U32/U38/U39/U46，D02–D04/D07/D09。
- 步骤：核对正常POST与真断连、keep-alive清理、NDJSON空bytes/code、未知方言ID碰撞、例程读取失败不生成DROP、树刷新、格式化保真、Windows原子写重试、流错误结算及旧MySQL PK/分页。
- 验证：HTTP使用真实loopback；SDK明确子进程或内存通道；持久化使用合成临时文件及受控失败注入；不得访问实际用户配置。
- 验收：提交/写入结果不被刷新失败掩盖；原子写失败保留原文件；字节值、错误码和取消语义穿过真实消费入口。

### P06 · P2 · 平台、CI与文档已有修复复核

- 关联：F07–F09/F13/F14，U21–U28/U41–U45。
- 步骤：检查CRLF/LF、Windows路径/URL、测试清单hash、fixture零测试拒绝、host feature门禁、专用库闸门、状态错误提前return、文档命令路由与事务范围。
- 验证：正负例同时覆盖；故意零测试、缺预期名称、改变保护顺序必须失败；平台跳过单列；CI代码核对不等于远端CI运行成功。
- 验收：不换hash逃避失败、不将核心失败变SKIP；所有发布/运行描述与当前入口匹配。

### P07 · P1 · 稳定游标契约收口

- 关联：U01，依赖P03。
- 关键问题：超预算回退live重查仍可能重复副作用，stable布尔并不能自动保证产品安全。
- 步骤：追踪stable从驱动到协议、core、UI、导出、完整值入口的全部消费；对比“超预算拒绝”与“用户显式选择live模式”，由总管给用户提交一次契约决定。
- 推荐：稳定结果作为默认；无法稳定保留时明确拒绝或要求显式选择，不静默重执行带副作用查询。
- 验证：random/UUID/nextval只执行一次、翻页/全文保持身份；超预算行为可见；预算覆盖累计游标和关闭释放。
- 停止条件：契约未确定不自行增大预算或把live路径标成已彻底修复。

### P08 · P1 · 旧MySQL与PostgreSQL事务边界

- 关联：D01/D05，依赖P05。
- 范围：旧两SQL驱动和事务消费层；与其它driver任务串行。
- 步骤：先复现普通DML、RETURNING、手写BEGIN/COMMIT/ROLLBACK、DDL隐式提交的差异；确定typed事务与SQL事务策略；按“是否写入”和“是否返回行”独立分类。
- 验证：隔离双连接观察提交前不可见、回滚恢复、DDL执行前保护、pending准确；不同错误不错误推断整事务回滚。
- 验收：网格与工作台共享事务事实；返回行形态不绕过写保护；缺真实库时标环境受阻，不声称内存测试证明事务安全。

### P09 · P1 · SDK事务超时隔离

- 关联：D06，依赖P05。
- 步骤：核对桌面已有未知结果策略；实现超时后句柄不可继续用、拒绝在途请求、终止并等待宿主、忽略晚到帧；commit结果未知使用明确错误；仅关闭自身宿主。
- 验证：合成宿主可控延迟/退出，缩短测试超时；确认超时后不再发送第二业务请求、pending全部结算、无孤儿进程；连接失败与提交未知区分。
- 验收：不能把超时写成“未提交”；重连恢复路径与SDK文档一致。

### P10 · P1 · 结构比较计划可靠性

- 关联：U33–U37/U40，依赖P03/P04；写入src/core/compare及metadata契约时独占。
- 步骤：先列支持矩阵：类型、NULL/default、PK/FK/UNIQUE/CHECK、表达式索引、identity/generated；可信元数据缺失时警告并停止对应自动计划；不把未知当成空。
- 修复顺序：PG类型/默认值/可空分开 → SQLite新建内联约束与既有表不支持提示 → 索引表达式 → 外键动作 → 同名约束变化/删除 → identity/generated元数据。
- 验证：每项单独反例；执行生成SQL后重新capture/diff；破坏性项只生成审阅计划，测试仅隔离合成库，不操作生产。
- 验收：不支持即明确显示，不产生看似完整却语义错误的同步SQL。需要重建表策略时交用户裁决，不自动实施通用重建。

### P11 · P2 · SQL脚本词法边界

- 关联：U31，依赖P05/P10相关文件释放。
- 步骤：复现SQLite反引号/方括号内分号、trigger CASE/END、PG E字符串及嵌套注释；按实际方言规则补状态，不用字符串替换。
- 验证：真实splitStatements/参数绑定消费者；多语句、注释、错误位置、未闭合状态、格式化前后；合法SQL不误切，非法SQL明确拒绝。
- 验收：原生与legacy共享消费者均覆盖；不偷偷扩大支持方言。

### P12 · P2 · CSV/BLOB交换契约

- 关联：D15/D16及legacy CSV/JSON导出补充发现。
- 决策：BLOB保持只读还是另立Hex编辑；当前页CSV仅展示还是支持可往返交换。
- 推荐：本轮保留BLOB只读，专项验收明确预期拒绝；CSV公开NULL标记与quoted空串规则，再按明确契约实现。重复列名和__proto__等JSON键不能静默丢值。
- 验证：NULL/空串/字面量NULL标记/换行/引号/BLOB/重复列名分别覆盖，导出导入逐字段一致或明确拒绝。
- 验收：生产能力、UI、测试、文档一致；不能为了测试期望新增未经决定的编辑能力。

### P13 · P2 · 剩余性能与生命周期

- 关联：D08/D12/D17及补充审查发现的grid监听器/分页失败循环/TransactionController初始化。
- 步骤：先确认实际消费入口和触发；用受控失败复现无限重试、关闭后监听器保留、无活动事务却阻止退出；修确定缺陷。artifact扫描先测固定规模I/O和延迟，不先造缓存。
- 验收：关闭后不再请求、不保留全局监听器；失败不会无退避循环；staging保留则匹配实际ResultRow；无consumer只列清理候选，不删除。

### P14 · P1 · 测试可信度与夹具安全

- 关联：U25–U28/U41–U45，以及审查中MySQL/DDL/TLS/SSH测试假绿与预删发现。
- 步骤：核查错误是否被catch后SKIP、Promise ID是否已await、负例是否匹配目标语义、缺CA是否被当TLS失败、首次SSH无指纹是否被当成功、固定emp/dept/schema是否会预删。
- 验证：注入目标失败必须非零；正确业务拒绝与无效输入异常分离；专用库未授权时在连接/DDL前拒绝；随机对象只创建不预删，留存证据。
- 验收：不运行原有危险夹具验证其危险性；支持平台的核心回归不能静默跳过。

### P15 · P2 · 补齐阅读覆盖与维护范围

- 关联：报告R01–R07、D13/D14/D17。
- 步骤：建立跟踪文本文件覆盖清单，标全文/分段/未读及理由；补齐自有代码和关键测试未读段；历史计划按历史属性读取，不作为现行契约；敏感evidence、二进制、锁文件、第三方vendor明确排除和审查方法。
- 决策：legacy/HTTP/SDK支持级别、SDK环境继承、无consumer组件/样式去留。
- 验收：不把目录枚举计为阅读；不能宣称第三方依赖完整安全审计；清理候选保留且有消费者证据，不删除。

### P16 · P0 · 集成验证与交付证据

- 前置：所有拟交付代码停止修改，各文件写入者已回报。
- 步骤：总管亲自看最终diff；运行允许的类型/编译/回归/负例；记录每个可观察表面；对当前最终代码重新取得证据，不拼接旧工作树测试结果。
- 验收：失败与跳过单列；没有证据的结论降为未验；每个补丁都能追到问题、测试和消费入口。

### P17 · P0 · 独立审查与统一门禁

- 前置：P16。
- 步骤：先运行既定pre_cc_selfcheck及自测；准备声明→出处→证据原文；独立上下文分别审需求覆盖和实现规范；合并交付物只挂一次首次cc门禁。
- 验收：核心缺陷或证据缺失为FAIL；主代理处理失败，最多首次+两次复核；不以门禁FAIL取得额外生产写权限。PASS后语义变更必须复核。
- 边界：静态PASS不证明真实DB/桌面/安装器可用。

### P18 · P0 · 最终交付与剩余问题承接

- 前置：P17通过，或达到上限后如实停止并交付阻塞事实。
- 产出：现有台账当前状态、最终补丁摘要、精确验证记录、剩余风险的优先级/承接人/后续任务。
- 格式：已验证 / 刻意未验 / 不可宣称。未解决项不消失，需用户决策集中一次提交，最多5个顶层问题。
- 不自动提交、推送、开PR或发布；这些动作按用户后续明确指示进行。

## 6. 给用户的五项集中决策

执行者先完成相关事实取证，由总管再提交；不是启动P00–P06的前置审批。

1. 稳定游标：推荐默认稳定，超预算显式拒绝或显式live模式，禁止静默重查。
2. legacy维护等级：推荐保留HTTP/SDK现有消费者，当前只修数据安全与明确契约问题，暂不删除旧实现。
3. 结构同步边界：推荐可信元数据不足时拒绝相应自动SQL；通用SQLite重建另立范围。
4. BLOB/CSV：推荐BLOB维持只读；CSV确定无损交换契约后再实现，不混用展示导出。
5. SDK隔离：推荐事务超时强制隔离宿主；环境过滤按明确允许规则实施，不复制真实环境内容。
